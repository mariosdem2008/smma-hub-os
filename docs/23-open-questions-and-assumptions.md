# 23 Open Questions And Assumptions

| Related | [14-mvp-scope](14-mvp-scope.md), [16-technical-architecture](16-technical-architecture.md), [20-launch-assumptions-and-go-to-market](20-launch-assumptions-and-go-to-market.md) |

## 1. Open Questions

| Question | Why it matters |
|---|---|
| Which agency segments should launch first? | Affects onboarding depth, pack templates, and GTM language |
| Which source types are mandatory for MVP readiness? | Affects ingestion scope and evaluation quality |
| Which integrations are launch-critical? | Affects architecture and implementation sequencing |
| How much autonomy is acceptable in v1? | Affects trust, cost, and review design |
| Which client portal actions belong in launch scope? | Affects permissions and UX complexity |

## 2. Working Assumptions

- agencies will accept moderate setup if value appears early
- human approval remains important for client-facing work
- the operating model will need revision after pilot usage
- strategy quality is a stronger wedge than raw content speed

## 3. Risk Areas

- over-customization
- under-defined source truth
- pack sprawl
- weak portal quality
- scope creep into CRM or PSA territory

## 4. Resolution Rule

Unknowns should be recorded and resolved explicitly. No unresolved assumption should silently become shipping behavior.
