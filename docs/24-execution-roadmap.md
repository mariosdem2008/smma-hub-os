# 24 Execution Roadmap

| Related | [14-mvp-scope](14-mvp-scope.md), [21-launch-acceptance-criteria](21-launch-acceptance-criteria.md), [23-open-questions-and-assumptions](23-open-questions-and-assumptions.md) |

## 1. Roadmap Shape

The roadmap should move from governed foundations to intelligence to repeatable execution to scaled specialization.

## 2. Phases

| Phase | Goal | Exit outcome |
|---|---|---|
| Foundation | Encode tenant model, agency model, and core records | Agency and client truth can persist safely |
| Intelligence | Add packs, retrieval, strategy generation, and grading | Governed briefs are useful and traceable |
| Execution | Add tasks, approvals, portal, and operational state | Work can move end to end in one system |
| Scale | Add specialist agents, optimization, and deeper integrations | The platform compounds agency leverage |

## 3. Milestone Themes

1. tenant isolation and core data model
2. agency setup and pack governance
3. client onboarding and source ingestion
4. strategy generation and grading
5. work items, approvals, and portal collaboration
6. agent orchestration, evaluation, and feedback loops

## 4. Delivery Rules

- build source quality before autonomy
- build approvals before escalation-heavy automation
- build client-facing trust in parallel with internal workflow power
- build fewer coherent flows before many shallow surfaces

## 5. Operating Standard

Every phase should make the platform more governed, more repeatable, and more valuable for real agency work.
